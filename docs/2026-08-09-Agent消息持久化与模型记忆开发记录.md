# Agent 消息持久化与模型记忆开发记录

> 日期：2026-08-09
> 状态：实现完成，已通过真实 PostgreSQL 与真实千问模型验证

## 一、开发目标

把原来由浏览器临时维护并随请求上传的最近历史，改造成真正的服务端持久化记忆，并验证：

1. 用户与助手消息确实写入 PostgreSQL；
2. 新建的请求级 Agent 能从数据库拿到历史；
3. 第二次模型请求不上传历史正文时，模型仍能回忆第一轮信息；
4. 页面刷新后能从服务端恢复历史消息。

## 二、原有问题

原实现中的 `ModelChatRequest.history` 由浏览器 `state.messages` 生成。服务端没有消息表，
页面刷新或更换客户端后历史就会丢失，也无法证明模型上下文来自可信的服务端记录。

这次修改后，请求体只包含：

```json
{
  "message": "当前用户消息",
  "conversation_id": "可选 UUID"
}
```

客户端不能再把任意历史数组直接注入模型上下文。

## 三、实现内容

### 3.1 数据模型

新增两张 PostgreSQL 表：

- `chat_conversations`：保存会话 ID、站点、用户、模式、摘要预留字段和时间；
- `chat_messages`：保存消息 ID、会话 ID、递增序号、角色、正文和时间。

消息通过 `(conversation_id, sequence)` 唯一约束保持顺序。会话读取始终同时校验 site、
user_id 和 mode，防止跨用户或跨模式读取历史。

### 3.2 服务端记忆链路

每轮请求执行以下流程：

1. 校验已有 `conversation_id` 的所有权，或创建新会话；
2. 从 PostgreSQL 加载最近的持久化消息；
3. 按 `CHAT_HISTORY_MAX_MESSAGES` 和 `CHAT_HISTORY_MAX_CHARS` 裁剪上下文；
4. 在模型调用前保存并提交当前用户消息；
5. 创建新的请求级 Agent，并传入“数据库历史 + 当前消息”；
6. 聚合流式文本，在发送 `done` 事件前保存并提交助手消息。

Agent 实例仍然是请求级临时对象，不保存 OAuth Token、MCP Client 或内存会话。所谓“记忆”
来自 PostgreSQL，而不是某个常驻 Python 对象。

### 3.3 历史恢复与前端

新增：

```text
GET /api/v1/chat/history?mode=model|agent&conversation_id=<optional UUID>
```

不提供会话 ID时返回当前登录用户在该模式的最近会话。前端切换模式或刷新页面时调用该接口，
并分别保存模型模式和 ERPNext Agent 模式的会话 ID。

### 3.4 配置

新增环境变量：

```dotenv
CHAT_HISTORY_MAX_MESSAGES=20
CHAT_HISTORY_MAX_CHARS=24000
CHAT_HISTORY_DISPLAY_LIMIT=100
```

前两个控制实际送入模型的历史预算，最后一个控制历史接口单次返回数量。

## 五、真实数据库与模型验证

执行：

```bash
docker compose exec -T agent python -m erpnext_agent.memory_smoke
```

验证程序在运行时生成不可预知的随机码，第一轮要求千问记住，第二轮只发送问题和
`conversation_id`，没有发送历史正文。实测结果：

```json
{
  "database_message_count": 4,
  "database_roles": ["user", "assistant", "user", "assistant"],
  "history_api_message_count": 4,
  "memory_code_recalled": true,
  "first_reply": "已记住。"
}
```

随后直接使用 SQL 查询同一会话，结果依次为：

```text
1 user      请记住随机码 MEM-...。只回复：已记住。
2 assistant 已记住。
3 user      我上一条让你记住的随机码是什么？只回复随机码。
4 assistant MEM-...
```

因此可以确认：消息已经实际写入 PostgreSQL；第二轮新建 Agent 的回答依赖服务端加载的历史，
不是浏览器回传历史，也不是复用上一次 Agent 对象。

## 六、当前边界

- 已实现最近消息窗口，尚未实现超长会话自动摘要；
- 本阶段当时只实现最近会话恢复；后续已补齐新建和列表 UI，详见
  `2026-08-09-Agent前端历史会话与新建对话优化记录.md`，重命名和删除仍未实现；
- 当前开发环境使用 `create_all` 增量建表，生产环境仍需 Alembic 等正式迁移；
- 模型调用失败时用户消息会保留，便于审计，但尚未增加失败状态字段和 UI 重试入口；
- 尚未制定历史消息归档、保留期限和用户删除策略。

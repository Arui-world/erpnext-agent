# Agent 前端历史会话与新建对话优化记录

> 日期：2026-08-09
> 状态：实现完成，已通过真实接口、数据库和模型联合验证

## 一、问题确认

用户反馈页面刷新后看不到历史，并且没有新增对话功能。检查真实 PostgreSQL 时发现：数据库
只有自动记忆测试用户的会话，没有当前浏览器实际 ERPNext 用户的会话记录。同时旧前端只会
请求“最近一个会话”，没有可见的会话列表；左侧“新对话”和“对话记录”图标只是禁用的视觉
占位，无法操作。

因此本次不仅修复刷新加载流程，还补齐了完整的多会话前端入口。

## 二、后端能力

新增接口：

```text
GET  /api/v1/chat/conversations?mode=model|agent
POST /api/v1/chat/conversations
```

列表接口按当前 OAuth Session 的 site、user_id 和模式查询，返回：

- `conversation_id`；
- 由首条用户消息生成的安全标题；
- 消息数量；
- 创建和更新时间。

创建接口要求 Session Cookie 和 CSRF Token，每次生成独立 UUID。新会话不会复用旧消息，
之后发送消息时继续沿用既有的 PostgreSQL 持久化和模型历史加载链路。

新增配置：

```dotenv
CHAT_CONVERSATION_LIST_LIMIT=50
```

## 三、前端优化

页面现在包含响应式历史会话侧栏：

- 桌面端默认展示历史栏，可通过左侧记录按钮收起；
- 移动端以抽屉形式展示，并提供遮罩关闭；
- 顶部“新对话”和左侧加号都能创建独立会话；
- 会话项显示标题、消息数和最近更新时间；
- 当前会话具有明确选中状态；
- 点击历史项后按其 `conversation_id` 加载 PostgreSQL 消息；
- 切换模型/Agent 模式时分别加载对应会话列表；
- 页面刷新时先取列表，再恢复最近或当前可用会话；
- 每轮回复完成后自动刷新列表标题、消息数和顺序。

## 五、当前边界

- 已支持创建和切换，尚未支持重命名与删除；
- 空白新会话会立即保存在数据库中，后续可增加空会话自动清理；
- 会话标题当前取首条用户消息，尚未调用模型生成摘要标题；
- 当前列表上限为 50，尚未实现分页或无限滚动；
- 用户需要在新版本部署后重新发送一条消息，旧版仅存在浏览器内存中的消息无法从数据库恢复。

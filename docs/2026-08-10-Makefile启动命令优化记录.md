# Makefile 启动命令优化记录

> 日期：2026-08-10
> 状态：完成

## 一、问题

原来的 `make up` 固定执行：

```bash
docker compose up --build -d
```

这会在每次日常启动时都触发镜像构建检查。修改过源码、README 或依赖层时，还会重新执行
项目安装与 Python 字节码编译，使普通启动等待时间明显增加。

## 二、修改结果

现在 Makefile 提供以下职责清晰的命令：

| 命令 | 作用 |
|---|---|
| `make up` | 使用现有镜像启动 Compose 服务，不强制构建 |
| `make rebuild` | 重新构建 Agent 镜像并启动全部服务 |
| `make restart` | 只重启 Agent 容器 |
| `make logs` | 持续查看 Agent 日志 |
| `make ps` | 查看 Compose 服务状态 |
| `make down` | 停止并删除 Compose 容器 |

使用建议：

- 首次启动或修改 Python 代码、依赖、Dockerfile 后使用 `make rebuild`；
- 仅启动现有环境时使用 `make up`；
- 只需要重启进程且配置没有变化时使用 `make restart`；
- 修改 `.env` 后应使用 `docker compose up -d --force-recreate agent`，不能只执行 restart。

## 三、验证

通过 Make dry-run 核对每个目标展开后的命令，并执行 Docker Compose 配置检查。验证标准：

- `make up` 不包含 `--build`；
- `make rebuild` 包含 `--build`；
- restart/logs/ps/down 均指向预期 Compose 子命令；
- `docker compose config --quiet` 通过。

# Agent 库存查询无文本回复修复记录

> 日期：2026-08-10
> 状态：修复完成，已通过真实 OAuth、MCP、模型、SSE 和 PostgreSQL 联合验证

## 一、问题现象

在 ERPNext Agent 模式中输入“查看当前库存”后，模型会询问物料编码和仓库名称。用户继续输入
“test item1在仓库的库存”时，页面曾显示：

```text
抱歉，本次对话失败：模型没有返回文本内容
```

数据库中当时只保存了用户的第三条消息，没有对应的助手回复。

## 二、根因分析

运行日志中存在明确证据：

```text
Agent data_agent exceeds the max iteration numbers 8. Stop the react loop.
```

进一步检查发现四个相关问题：

1. 自定义 `ERPNextMCPTool` 已等待 MCP 请求完成，但成功结果仍被标记为
   `ToolResultState.RUNNING`，AgentScope 不能将其视为完成终态。
2. Data Agent 的旧提示没有明确要求库存工具必须先收齐精确的 `item_code` 和完整
   `warehouse`，模型在参数不完整时可能反复尝试枚举。
3. 确定性意图门控只检查当前消息。用户单独补充 `Stores - TQC` 时，无法继承上一轮
   库存查询意图。
4. 流式接口在 `ReplyEndEvent` 已到达但文本为空时，只发送 `done`，导致前端只能给出
   通用的“模型没有返回文本内容”。

## 三、实现修复

### 3.1 MCP 完成终态

同步等待 MCP 完成的 `ToolBase.call()` 现在返回：

```python
state=ToolResultState.SUCCESS
```

单元测试已固定这个契约，防止后续再把完成工具退化为 `RUNNING`。

### 3.2 库存参数澄清

Data Agent 增加以下硬规则：

- 只有同时收到精确物料编码和完整仓库名称才调用库存工具；
- 任一参数缺失时用文本询问，不自行枚举所有物料或仓库；
- 只有用户明确要求候选值时才使用 `erpnext_get_list`；
- 禁止以相同参数重复调用工具。

### 3.3 多轮上下文路由

新增 `IntentGate.route_with_context()`。当前消息本身已能判断意图时，仍完全以当前消息
为准；只有当前消息不完整时，才从 PostgreSQL 加载的历史中继承最近一条明确用户意图。

因此 `Stores - TQC` 可作为上一轮库存问题的参数继续进入 Data Agent，同时当前消息中的
删除、提交、创建等明确安全意图仍优先。

### 3.4 空文本流式兜底

如果 AgentScope 发出结束事件但没有文本，后端会通过 `text_delta` 返回可重试提示，并在
`done` 之前将该提示持久化。前端不再收到“只结束、无文本”的流。

## 四、真实链路验证

验证使用已加密存储的 Administrator OAuth 凭据，运行期不输出 access token、refresh token 或
密文。MCP 先确认了真实业务值：

```text
item_code: test item1
warehouse: Stores - TQC
```

最终新会话 `5de0335a-9899-46ce-9fb4-d725851a0812` 按顺序执行：

1. 用户：`查看当前库存`；
2. Agent：询问物料编码与完整仓库名称，未调用工具；
3. 用户：`test item1在仓库的库存`；
4. Agent：只询问缺失的完整仓库名称，未调用工具；
5. 用户：`Stores - TQC`；
6. Agent：只调用一次 `erpnext_get_stock_balance`，返回库存结果。

实际回复中的业务结果：

```text
物料编码：test item1
仓库：Stores - TQC
实际库存数量：0.0 Nos
库存价值：0.0 INR
```

同一会话的 6 条 user/assistant 消息已全部保存到 PostgreSQL。最终容器日志中没有新的
`max iteration numbers 8` 告警。

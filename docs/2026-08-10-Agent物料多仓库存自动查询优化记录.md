# Agent 物料多仓库存自动查询优化记录

> 日期：2026-08-10
> 状态：实现完成，已通过真实 OAuth、MCP、SSE 和 PostgreSQL 联合验证

## 一、优化目标

旧库存流程要求用户同时给出精确物料编码和完整仓库名称。对于“`test item1的库存`”这类
常见问题，用户通常并不知道该物料存放在哪些仓库，因此要求先选仓库不符合使用习惯。

本次目标是：用户只需给出物料，Agent 自动返回该物料在所有正库存仓库中的数量。

## 二、MCP 能力确认

当前 ERPNext MCP 的通用只读白名单包含 `Item` 和 `Bin`，`erpnext_get_list` 会按当前 OAuth
用户执行 Frappe RBAC、User Permission 和字段权限检查。真实调用确认 Bin 可读字段包括：

```text
item_code, warehouse, actual_qty, reserved_qty, projected_qty,
valuation_rate, stock_value
```

以下过滤器已通过真实 MCP 验证：

```json
{
  "item_code": "test item1",
  "actual_qty": [">", 0]
}
```

## 三、实现方案

### 3.1 常见问法提取

新增无仓库物料库存语句提取，支持：

```text
test item1的库存
查询物料 test item1 库存
test item1在所有仓库的库存
```

“查看当前库存”没有物料信息，仍进入原有澄清流程；已包含具体仓库的复合问法仍交给
Data Agent 和 `erpnext_get_stock_balance`。

### 3.2 确定性权限感知查询

新增 `InventoryService`，流程为：

1. 使用加密存储的当前用户 OAuth access token；
2. 调用 MCP 当前用户工具，核对 Agent Session 和 ERPNext 身份；
3. 按 Item `name` 查找精确物料，未命中时按 `item_name` 查找；
4. 唯一匹配时查询 `Bin`，强制 `item_code` 相等且 `actual_qty > 0`；
5. 每页 100 条，最多 10 页，最多返回 1000 个正库存仓库；
6. 输出每个仓库的实际、预留、预计数量和实际库存合计。

该路径不直连 ERPNext 数据库，不使用 Administrator 全局密钥，不绕过 MCP 和 Frappe 权限。

### 3.3 Chat 与 SSE

同步 Chat 和流式 SSE 均已接入确定性库存服务：

- 用户消息先持久化；
- 对话仍返回 `conversation_id`；
- SSE 仍发送 `tool_call_start`、`tool_result_start`、`tool_result_end`、`text_delta` 和 `done`；
- 助手结果在 `done` 前写入 PostgreSQL；
- 高频固定查询不再依赖大模型反复规划 `erpnext_get_list`。

Data Agent 提示同步更新，作为复杂口语化问题未命中确定性路径时的备用策略。

## 四、真实验收

验收使用 Administrator 的现有 OAuth 凭据，未输出 access token、refresh token 或密文。

用户只发送：

```text
test item1的库存
```

没有提供仓库名称，Agent 没有追问仓库。实际工具序列为两次 `erpnext_get_list`：第一次解析
Item，第二次查询正库存 Bin。

真实回复：

```text
物料 test item1 在以下仓库有正库存：

仓库：仓库 - rw
实际库存：10.0 Nos
预留数量：0.0 Nos
预计数量：10.0 Nos
合计实际库存：10.0 Nos
```

会话 ID：`10279862-b845-451c-b4e6-587a2c590a60`。PostgreSQL 中存在完整的 user/assistant 两条
消息，助手历史内容与 SSE 回复完全一致。

## 六、当前边界

- 确定性语句提取覆盖常见无仓库问法，复杂复合问题仍由 Data Agent 处理；
- 为防止无界扫描，单次最多返回 1000 个正库存仓库，达到上限会在回复中明确说明；
- 本次真实验收使用 Administrator，尚需第二个低权限用户验证 Item/Bin 权限差分；
- 这一查询只返回 `actual_qty > 0` 的仓库，零库存和负库存不在结果中。

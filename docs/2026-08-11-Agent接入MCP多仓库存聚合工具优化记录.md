# Agent 接入 MCP 多仓库存聚合工具优化记录

> 日期：2026-08-11
> 状态：实现完成，已通过真实 OAuth、模型、MCP、SSE 和 PostgreSQL 联合验证

## 一、优化原因

旧实现在 Chat API 中用正则识别常见库存问法，再由 `InventoryService` 直接调用通用
Item/Bin 查询并拼装回复。它仍经过 OAuth、MCP 和 Frappe 权限，但库存问法判断、工具序列和
回复格式都由后端确定，用户合理地质疑它是“硬编码回答”。

MCP 端现已新增 `erpnext_get_item_stock_by_warehouses`，因此本次将该路径恢复为标准的
“Data Agent 理解请求 → 调用领域 MCP 工具 → 根据工具结果生成回复”。

## 二、MCP 契约确认

已阅读并核对 `ERPNext-MCP-使用文档.md`。实际 `tools/list` 返回 14 个工具，新工具契约为：

```json
{
  "name": "erpnext_get_item_stock_by_warehouses",
  "required": ["item_code"],
  "readOnlyHint": true
}
```

实际直接调用 `item_code=test item1` 返回：

```text
stock_uom=Nos
warehouse=仓库 - rw
company=锐雯
actual_qty=10.0
projected_qty=10.0
totals.actual_qty=10.0
```

返回范围是当前用户可见、已存在 Bin 的叶子仓库。工具不返回或汇总库存价值，不支持历史日期。

## 三、实现内容

### 3.1 删除硬编码路径

- 删除 `src/erpnext_agent/inventory.py` 及其单元测试；
- 删除 Chat/SSE 中的库存正则识别和特判分支；
- 删除专用回复拼接和伪造工具事件；
- 删除 FastAPI app state 中的 `InventoryService`。

因此现在“`test item1的库存`”不会在 Chat API 被截获，而是进入真实 AgentScope 工具循环。

### 3.2 接入新 MCP 工具

- 将新工具加入本地只读契约和 Agent 工具白名单；
- Data、Patrol、Action 可调用，Orchestrator 仍不持有工具；
- 本地严格契约数量从 13 更新为 14；
- Data Agent 仅给出物料时，必须把用户文本原样作为 `item_code`，单次调用聚合工具；
- 不先行查 Item/Schema，不查通用 Bin，不逐仓循环 `erpnext_get_stock_balance`；
- 指定完整仓库时仍保留单仓库存工具路径。

### 3.3 可重复真实验收

新增 `python -m erpnext_agent.stock_smoke`，它会：

1. 查找指定用户已存储且未撤销的 OAuth 凭据；
2. 创建临时 Agent Session，不输出 token 或密文；
3. 请求真实 `/api/v1/chat/stream`；
4. 断言工具序列严格等于单次聚合工具；
5. 断言助手回复和 user/assistant 两条消息已落库；
6. 删除临时 Redis Session。

## 四、真实链路验收

验收用户：`Administrator`，输入：

```text
test item1的库存
```

最终工具序列：

```text
[erpnext_get_item_stock_by_warehouses]
```

真实回复包含：`stock_uom=Nos`、`仓库 - rw`、`锐雯`、`actual_qty=10.0`，并明确不汇总库存价值。
会话 ID 为 `3948e148-6e51-4e9e-a74f-f2ade2f9dd0c`，PostgreSQL 持久化角色顺序为
`[user, assistant]`。

首次真实检查曾发现模型仍先调用通用 Item/Schema 工具，严格 smoke 正确地拒绝了该结果。
收紧 Data Prompt 的“首个且唯一工具”规则后复测通过，证明最终验收观测的是真实 Agent 决策。

## 六、当前边界

- 本次实际验收使用 Administrator，尚需第二个低权限用户做权限差分验证；
- MCP 多仓工具是当前 Bin 快照，历史日期和单仓估值仍使用 `erpnext_get_stock_balance`；
- OAuth access token 自动刷新仍未实现；本次验收前使用现有 refresh token 刷新了存储凭据；
- `stock_smoke` 要求显式传入 `STOCK_SMOKE_USER_ID` 与 `STOCK_SMOKE_ITEM_CODE`，不在业务代码中预置验收用户或物料。

# Token 自动刷新与长对话摘要开发记录

> 日期：2026-08-11
> 状态：功能已部署且 readiness 通过，真实 token 轮换和模型摘要 smoke 待授权

## 一、本次目标

解决 OAuth access token 超时后用户立即被退出、必须重新登录的体验问题；同时为长对话增加
可持久化的增量摘要，防止完整历史无限进入模型上下文。

实现始终遵守两个边界：

- 不使用 Administrator 或其他高权限凭据作为用户 token 失效后的回退；
- 摘要是受限的上下文数据，不是新指令、新授权或原始消息的替代审计记录。

## 二、OAuth Token 自动刷新

新增 `TokenRefreshService`，并在 Agent 运行时创建 MCP Client 前读取有效凭据：

1. access token 距过期默认不足 120 秒时，主动调用 OAuth refresh grant；
2. 同一 credential 使用 Redis `SET NX EX` 获取分布式租约，只有所有者才能通过 Lua 释放；
3. 未获得锁的并发请求会重读数据库，复用胜出者写入的新 token；
4. ERPNext 未轮换 refresh token 时保留原加密值，不用空值覆盖；
5. MCP 首次认证失败时强制刷新并重试原工具调用一次；
6. refresh token 缺失/失效或第二次认证失败时，清理 Agent Session 并返回
   `REAUTHENTICATION_REQUIRED`。

锁键使用 credential ID 的 SHA-256 结果，异常、日志和 smoke 输出都不包含 access token、
refresh token 或 Client Secret。如果并发刷新等待超时，但当前 access token 尚未真正过期，
请求仍可继续使用当前 token，避免单纯因为提前刷新失败就迫使用户退出。

## 三、长对话自动摘要

新增无工具的摘要 Agent 和 `ConversationMemoryService`：

- 默认在会话达到 16 条消息或 16000 字符时触发；
- 保留最近 8 条原始消息，只摘要以 assistant 结束的完整旧轮次；
- 每次摘要源默认最多 24000 字符，摘要最多 4000 字符，超限时按完整轮次分批增量合并；
- `chat_conversations.summary` 保存版本化 JSON 信封，使用 `through_sequence` 记录已摘要边界；
- 写入前锁定会话并拒绝过时 sequence，同时用 Redis 非阻塞租约避免多请求重复摘要；
- 向主 Agent 注入的摘要显式标记为“系统生成的上下文数据”，摘要 Prompt 拒绝执行历史中的提示注入；
- 生成失败时回滚并使用最近消息继续当前对话。

摘要不会删除 `chat_messages`；页面历史、审计和后续数据保留策略仍以完整原始消息为准。

## 四、配置项

`.env.example` 新增以下配置，未在 `.env` 显式覆盖时使用安全默认值：

```dotenv
OAUTH_REFRESH_LEEWAY_SECONDS=120
OAUTH_REFRESH_LOCK_TTL_SECONDS=60
OAUTH_REFRESH_WAIT_SECONDS=25
OAUTH_REFRESH_POLL_SECONDS=0.1

CHAT_SUMMARY_ENABLED=true
CHAT_SUMMARY_TRIGGER_MESSAGES=16
CHAT_SUMMARY_TRIGGER_CHARS=16000
CHAT_SUMMARY_KEEP_RECENT_MESSAGES=8
CHAT_SUMMARY_SOURCE_MAX_CHARS=24000
CHAT_SUMMARY_MAX_CHARS=4000
CHAT_SUMMARY_LOCK_TTL_SECONDS=120
```

配置校验要求 `CHAT_SUMMARY_KEEP_RECENT_MESSAGES` 必须小于
`CHAT_SUMMARY_TRIGGER_MESSAGES`，避免配置为永远无法摘要的窗口。

## 六、真实验收边界

为真正证明功能在当前 ERPNext 和千问环境生效，验收步骤如下：

```bash
docker compose up --build -d agent
docker compose run --rm --no-deps -e TOKEN_REFRESH_SMOKE_USER_ID=Administrator agent \
  python -m erpnext_agent.token_refresh_smoke
docker compose run --rm --no-deps agent python -m erpnext_agent.summary_smoke
```

用户已明确允许重启，因此第一步已完成，容器和 readiness 均正常。第二步会真实轮换
Administrator OAuth token；第三步会消耗真实模型调用，创建并在结束时删除临时测试会话。
“允许重启”不扩展为对后两项操作的授权，因此不把 token/摘要记录为“真实 smoke 验收通过”。

验收标准：

- token smoke 刷新后 credential ID 不变、版本/更新时间前进，并能通过新 token 读取同一 MCP 当前用户；
- summary smoke 在不携带旧原文的最近窗口中，仍能从持久化摘要回忆随机码；
- PostgreSQL 中原始消息数量不因摘要减少；
- 重启后 `/health/ready` 显示 `oauth_auto_refresh=true` 和 `conversation_auto_summary=true`。
